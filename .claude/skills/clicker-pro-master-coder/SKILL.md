## 📋 Human Quality Code Standards

**Write code like a senior engineer — natural and professional.**

### ✅ Always Do
- **Complete files** — কোনো `// ... rest` বা placeholder নয়
- **Clean Architecture** + SOLID + DRY + KISS
- **Dart null safety** — `?.` `??` proper use, `!` সতর্কে
- **Named parameters** — widget constructors-এ
- **const constructors** — যেখানে possible
- **Error + Loading states** — সব async operations-এ
- **Separation of Concerns** — logic, UI, data আলাদা
- **BDT formatting** — `৳` symbol, Bangladeshi locale
- **Bilingual** — বাংলা + English labels যেখানে relevant
- **Dark Luxury Lens** — সব UI-তে design system follow করো
- **Descriptive names** — variable/method names self-documenting
- **Modular design** — reusable widgets, small focused files

### ❌ Never Do
- Placeholder রাখা (`TODO`, `// implement later`, `...`)
- Magic numbers (named constants ব্যবহার করো)
- God widgets (একটি widget সব কাজ করবে না)
- Hardcoded strings UI-তে
- setState() abuse — proper state management
- Unnecessary abstraction বা over-engineering
- Excessive comments on obvious code
- Duplicate logic (helper function বানাও)
- Unrelated refactoring (শুধু requested scope touch করো)

## 🐛 Bug Fix Framework

**Never patch symptoms. Fix root causes only.**

```
Problem
  → Root Cause Analysis
  → Impact Assessment (অন্য কোথাও ভাঙবে কি?)
  → Complete Fix (পুরো affected file)
  → Validation (edge cases covered?)
  → Prevention Note (ভবিষ্যতে এড়ানোর উপায়)
```

**Flutter/Dart Common Crash Patterns:**
```dart
// ❌ Null pointer
widget.title.length  // crash if null

// ✅ Safe
widget.title?.length ?? 0

// ❌ setState after dispose
setState(() { data = result; });

// ✅ Safe
if (mounted) setState(() { data = result; });

// ❌ BuildContext across async gap
Navigator.of(context).push(...)  // after await

// ✅ Safe
final nav = Navigator.of(context);
await someAsyncWork();
nav.push(...)
```

## 🎬 Animation & Motion System

- Natural feeling — ease curves, not linear
- Lightweight — no heavy computation on main thread

Flutter Animation Hierarchy:
1. AnimatedContainer / AnimatedOpacity (simplest)
2. TweenAnimationBuilder (custom single property)

4. Rive / Lottie (complex pre-built animations)

Avoid: Jank, lag, over-animation, simultaneous heavy animations

## 🔒 Security Framework

Always validate for:
```
Authentication:   Supabase JWT, session expiry, refresh
Authorization:    Role-based access (Owner/Manager/Freelancer/Both)
Input Validation: All user inputs sanitized before DB write
Secure Storage:   flutter_secure_storage for sensitive data
Data Protection:  No PII in logs, no secrets in code

Prevent:
- SQL Injection    → Supabase parameterized queries (auto)
- XSS             → No raw HTML rendering of user input
- Secret Leakage  → .env files, never hardcode API keys
- Token Exposure  → Secure storage only, never setState/print
```

## ⚡ Performance Excellence

```
Mobile (Flutter):
- Startup speed    → lazy loading, minimal main.dart
- Frame rate       → const widgets, RepaintBoundary
- Memory           → dispose controllers, cancel streams
- Battery          → avoid polling, use streams/websockets
- APK/AAB size     → tree shaking, compressed assets

Backend (Supabase):
- Query performance → proper indexes, .select() specific columns
- N+1 prevention   → join queries, not loop fetches
- Realtime         → subscribe only to needed tables/rows

Web (Landing Page):
- Lighthouse 90+   → compressed images, lazy loading
- Bundle size      → minimal JS, critical CSS inline
- Loading speed    → above-fold content first
```
